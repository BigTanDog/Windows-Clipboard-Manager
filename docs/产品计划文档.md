## 0. 决策基线（开工前评估 + 用户逐项确认，2026-09-18）

| 编号 | 议题 | 结论 |
|---|---|---|
| D-01 | 体积路线 | **双形态**。**形态 B（默认交付）**：框架依赖单文件，预计 1.5–3MB，目标机需装 .NET 8 Desktop Runtime；**形态 A（免运行时备选）**：自包含单文件 + 压缩，预计 55–80MB。两条发布命令均写入 README |
| D-02 | UI 框架与裁剪 | 维持 **WPF + .NET 8**。**不启用 `PublishTrimmed`、不启用 Native AOT** —— 微软官方《Known trimming incompatibilities》明确 WPF/WinForms 的裁剪已在 .NET SDK 中禁用，Native AOT 支持矩阵不含桌面 GUI 框架。需求 §2 的"裁剪后 15MB"对 WPF 不成立 |
| D-03 | 面板激活模型 | **弃用 `WS_EX_NOACTIVATE`**（否则拿不到键盘输入、也收不到 `WM_KILLFOCUS`）。面板正常激活以获取键盘焦点；弹出前记录 `GetForegroundWindow`，粘贴/关闭时恢复。保留 `WS_EX_TOOLWINDOW` + `TopMost` + 不显示在任务栏 |
| D-04 | 面板关闭方式 | **第一版不做"点击外部自动隐藏"** → 降级为附加项 B-01（**已完成，默认开启、设置可关**，见 §9）。第一版关闭手段：`Esc`、再次按全局热键、面板关闭按钮 |
| D-05 | 弹出位置 | **默认屏幕右下角**（光标所在显示器，任务栏上方），对齐系统 Win+V 观感。拖动与位置记忆 → 附加项 B-02 |
| D-06 | 排除应用 | **官方注册格式为主 + 来源进程名辅助**：优先读 `CanIncludeInClipboardHistory` / `CanUploadToCloudClipboard`（DWORD=0 即对方声明"不要进历史"）；辅助用 `GetClipboardOwner` → `GetWindowThreadProcessId` → 进程名过滤，设置中可关闭 |
| D-07 | `CF_BITMAP` | 第一版**不做**（→ 附加项 B-03）。第一版图片只认 `CF_DIB` / `CF_DIBV5` |
| D-08 | HTML 写回 | HTML 记录粘贴时**同时写回 `HTML Format` + `CF_UNICODETEXT`**（纯文本由去标签得到），保证记事本/终端等只认纯文本的程序可粘贴 |
| D-09 | 磁盘占用上限 | **纳入第一版**（需求外新增，已获用户批准）：200MB / 500MB / 1GB / 2GB / 不限制，默认 **500MB** |
| D-10 | 性能指标口径 | 空闲内存 ≤80MB、冷启动 ≤500ms **以阶段一实测数据为准**；超标立即上报并给方案，不拖到收尾。**阶段一实测**：冷启动 236.9ms ✅、面板弹出 7.2ms ✅、形态 B 体积 2.43MB ✅、形态 A 63.97MB（预期内）；**空闲内存 WorkingSet64 119.2MB ❌ 超标 / PrivateBytes 65.9MB ✅** → 内存口径待用户拍板（WPF 基线决定 WS 无法 ≤80MB，详见技术设计 §9.3） |
| D-11 | 运行时版本 | 维持 **.NET 8**（LTS 至 2026-11-10；到期前评估升级 .NET 10） |
| D-12 | 开发环境 | .NET SDK **8.0.425 装于 `D:\dotnet`**（含 `Microsoft.WindowsDesktop.App 8.0.31`）。本机 PATH 中 `C:\Program Files\dotnet` 在前且**不含 SDK**，故**一律使用 `D:\dotnet\dotnet.exe`**（由仓库 `scripts/*.ps1` 封装，用户无需记路径） |
| D-13 | 敏感信息脱敏显示 | **显示层脱敏，默认开启**（需求外新增，已获用户批准）：手机号 / 身份证 / 银行卡 / 邮箱 / 密钥令牌 / 密码键值等**只显示前几位**，其余用固定长度 `*` 掩码；设置界面提供总开关。**不改变存储与粘贴内容** —— 粘贴出去的仍是原文（否则工具失去意义），磁盘上仍为明文。自定义规则/白名单/可见位数 → 附加项 B-05 |

## 2. 技术选型与理由

| 层面 | 选择 | 理由 / 被否决项 |
|---|---|---|
| UI | WPF（`net8.0-windows`） | 需求 §2 首选；否决 WinUI 3（自包含部署需带 WinAppSDK 运行时，体积更大）与 Avalonia（换框架会推翻现有计划，仅在体积成为硬约束时重启评估） |
| 发布 | `PublishSingleFile`（**不裁剪**） | D-01、D-02 |
| Win32 互操作 | **CsWin32** 源生成器 + 自写薄封装层 | 需求 §2 推荐；减少手写 P/Invoke 出错 |
| 数据库 | `Microsoft.Data.Sqlite` | 轻量、无额外部署 |
| 图片解码 | WPF 原生 `BitmapSource` / `PngBitmapEncoder` | 不引 `System.Drawing.Common`（GDI+ 依赖、与裁剪/AOT 兼容性顾虑无关但要少一层原生依赖） |
| 图标提取 | `SHGetFileInfo` + `IImageList`（需要时） | 需求 §2；不使用 `System.Drawing.Icon` 作为主路径 |
| 测试 | xUnit（单测）+ 真实 SQLite 临时目录（集成测试） | AGENTS.md §2 |
| 日志 | 自写轻量滚动日志，`data/logs/app.log` | 内容截断 ≤50 字符（AGENTS.md §4，禁止输出完整剪贴板文本） |

## 3. 架构设计

### 3.1 项目结构（单解决方案，依赖方向自上而下）

```
ClipboardManager.sln
├─ src/ClipboardManager.App        # WPF 表现层：面板窗口、设置窗口、托盘、ViewModel（无业务逻辑）
├─ src/ClipboardManager.Core       # 领域模型与契约：ClipItem、ClipContentType、去重/淘汰规则、接口（无 UI、无 Win32）
├─ src/ClipboardManager.Interop    # 所有 Win32 封装：隐藏消息窗口与 WndProc、剪贴板读写、热键、SendInput、SHGetFileInfo、显示器与 DPI
├─ src/ClipboardManager.Storage    # Microsoft.Data.Sqlite + data/blobs 文件管理、哈希去重、原子写入
├─ tests/ClipboardManager.Tests    # xUnit：解析/去重/上限等纯逻辑 + Storage 集成测试
└─ scripts/                        # build.ps1 / test.ps1 / publish-fd.ps1（形态 B）/ publish-sc.ps1（形态 A），统一使用 D:\dotnet\dotnet.exe
```

依赖方向：`App → Core ← Storage`、`App → Interop`、`Interop → Core`；`Core` 不依赖任何其他项目（可纯逻辑单测）。

### 3.2 线程模型（AGENTS.md §3 铁律）

- **STA 主线**：WPF UI 线程（STA）创建 `HWND_MESSAGE` 隐藏消息窗口，承载 `AddClipboardFormatListener` 与 `RegisterHotKey`；**所有剪贴板读/写只发生在这条 STA 线程上**，禁止 `Task.Run`/线程池读剪贴板。
- **锁内只拷贝**：`OpenClipboard` 成功后，只在锁内把原始数据拷成托管对象（`string` / `byte[]` / 路径 `string[]`），随后**立即 `CloseClipboard()`**；PNG 编码、SHA256、写库、UI 更新一律在锁外（必要时后台线程），且只传纯托管数据，**绝不跨线程传句柄**。
- **自循环防护**：写回剪贴板前后不做假设（官方文档未写明 `WM_CLIPBOARDUPDATE` 是 post 还是 send），以 **`GetClipboardSequenceNumber` 精确过滤**（写完记录新序列号，收到同一序列号直接跳过）+「内容哈希 + 2 秒时间窗」兜底。
- 消息窗口与主 UI 窗口分离（需求 §3.1）：主窗口隐藏/销毁不影响监听。

### 3.3 关键类职责

| 类 | 职责 |
|---|---|
| `ClipboardMessageWindow` | 创建 `HWND_MESSAGE` 窗口、WndProc 分发 `WM_CLIPBOARDUPDATE` / `WM_HOTKEY`、注册与注销监听 |
| `ClipboardAccess` | `OpenClipboard` 重试（3–5 次 × 30–50ms，总上限 ~250ms）、锁内拷贝、`CloseClipboard`、序列号过滤 |
| `ClipItemFactory` | 按优先级探测格式（HDROP → DIB/DIBV5 → HTML Format → UNICODETEXT）并产出 `ClipItem` |
| `HtmlClipboardFormat` | 解析 `Version/StartHTML/EndHTML/StartFragment/EndFragment`（**UTF-8 字节偏移**）+ 边界校验 + 去标签生成纯文本 |
| `DibDecoder` | `CF_DIB`/`CF_DIBV5` → 32bpp alpha 处理 → PNG 字节（WPF 编码器） |
| `HotkeyManager` | `RegisterHotKey`/`UnregisterHotKey` + 注册失败检测与提示 |
| `PasteService` | 记录/恢复前台窗口、写回剪贴板（含 HTML+纯文本）、`SendInput` 注入 Ctrl+V、异常兜底为"已复制，请手动粘贴" |
| `HistoryRepository` | SQLite CRUD、`content_hash` 唯一索引去重、`updated_at` 升序淘汰查询 |
| `BlobStore` | `blobs/` 哈希命名、原子写入（临时文件 + 替换）、垃圾回收 |
| `RetentionService` | 条数上限 + 磁盘占用上限（D-09）+ 收藏保护 |
| `SettingsStore` | `data/settings.json` 读写（原子写 + 损坏兜底为默认值） |
| `AppPaths` | 程序目录定位：**优先 `Environment.ProcessPath`**，`AppContext.BaseDirectory` 作对照与回退 |

### 3.4 数据存储

```
<程序目录>/
├─ ClipboardManager.exe
└─ data/
   ├─ history.db          # SQLite：仅元数据与索引
   ├─ blobs/              # 图片、大段 HTML 本体，按内容哈希命名（天然去重）
   ├─ pinned/             # 收藏内容本体
   ├─ logs/               # app.log（滚动，内容截断）
   └─ settings.json
```

- 表结构按需求 §4.3（`clip_items`）+ 索引：`content_hash` 唯一、`updated_at` 降序、`is_pinned`。
- SQLite 参数：`journal_mode=DELETE`（**不用 WAL**，避免 U 盘/网络盘上 `-wal`/`-shm` 残留与锁问题）、`synchronous=NORMAL`、`busy_timeout=3000`、`foreign_keys=ON`。
- 启动自检 `data/` 可写性；不可写（如放在 `Program Files`）时给出明确提示，**不静默降级到 %APPDATA%**（需求 §5.5）。

### 3.5 磁盘占用上限策略（D-09）

- 计量口径：`blobs/` + `pinned/` 实际文件大小之和 + 元数据行文本长度估算。
- 触发：每次入库后异步检查；超限则按顺序淘汰 —— ① 非收藏中**体积最大**者优先，② 同级按 `updated_at` 最旧优先；**收藏永不自动淘汰**。
- 边界：若仅剩收藏仍超限 → 面板顶部提示"收藏已占用 X MB，超出上限"，由用户手动处理，不自动删除。
- 与条数上限同时生效，谁先触发谁执行；两个上限均在设置界面可调。

### 3.6 Win32 API 清单（**每个调用点都要注释：作用 + 调用注意事项**，AGENTS.md 硬性要求）

| API | 用途 | 关键注意事项 |
|---|---|---|
| `AddClipboardFormatListener` / `RemoveClipboardFormatListener` | 剪贴板变更监听与注销 | 必须配对；窗口销毁前注销，避免悬空通知 |
| `OpenClipboard` / `CloseClipboard` / `GetClipboardData` / `SetClipboardData` | 剪贴板读写 | 全局独占；失败重试；**锁内不做慢操作**；`SetClipboardData` 后所有权移交系统，不可自行释放 |
| `GetClipboardSequenceNumber` | 过滤自身写入 | 无需打开剪贴板即可读，用于自循环防护 |
| `RegisterHotKey` / `UnregisterHotKey` | 全局热键 | 可能被占用而失败，必须检测并提示；退出必须注销 |
| `DragQueryFile` | 取出 `CF_HDROP` 路径 | 先取数量再逐个取；路径长度校验 |
| `GetForegroundWindow` / `SetForegroundWindow` | 记录与恢复目标窗口 | 前台锁限制可能失败，需兜底 |
| `SendInput` | 注入 Ctrl+V | UIPI 会阻止向更高完整性级别窗口注入，失败要兜底提示 |
| `SHGetFileInfo` | 取文件类型图标 | 资源需释放；优先小图标尺寸 |
| `MonitorFromPoint` / `GetDpiForMonitor` | 多屏与 DPI 换算 | 物理像素 ↔ DIP 换算，PerMonitorV2 |

## 4. 高危坑与对策（需求 §5 + 我方补充）

| 坑 | 对策 | 验证方式 |
|---|---|---|
| 5.1 剪贴板自循环（最高危） | 不依赖布尔标志时序：`GetClipboardSequenceNumber` 精确过滤 + 内容哈希 2 秒时间窗兜底 | 集成测试：写回后断言记录数不变（验收 §8-6） |
| 5.2 `OpenClipboard` 失败 | 统一封装重试 3–5 次 × 30–50ms，总上限 ~250ms，失败记状态码（不记内容） | 用其它程序持续占用剪贴板时连续复制（验收 §8-7） |
| 5.3 持锁期间慢操作 | 锁内代码只允许拷贝；`CloseClipboard()` 必须在任何编码/IO/UI 之前（代码审查固定检查项） | 代码审查 + 复制 4K 截图时其它程序仍能正常粘贴 |
| 5.4 HTML 头解析 | 纯函数解析器；**按 UTF-8 字节偏移切片**；畸形样本（越界/负值/缺字段/超长）全量单测；优先 Fragment 回退 HTML 段 | 单测 8–10 个畸形样本 + 真实网页复制 |
| 5.5 便携与只读目录 | 启动自检 `data/` 可写性，失败给明确提示 | 放到只读目录启动一次，看提示 |
| 5.6 单文件程序目录 | 优先 `Environment.ProcessPath`；**两条发布形态都实测**目录定位 | 形态 A/B 各启动一次，检查 `data/` 落点 |
| 5.7 高 DPI / 多屏 | `app.manifest` 声明 PerMonitorV2；右下角定位用 `MonitorFromPoint` + DPI 换算 | 125% / 150% / 200% + 双屏各一次 |
| 5.8 裁剪/AOT 兼容 | **直接不启用**（D-02）；若未来要 JSON 序列化，统一用源生成器上下文 | 发布脚本中禁止出现 `PublishTrimmed`/`PublishAot` |

## 5. 三阶段实施计划

> 每阶段结束**必须停下来汇报**：① 实际做了什么 ② 怎么验证它确实工作（具体操作步骤）③ 与预期不符的问题。
> 每阶段完成即提交 Git commit（AGENTS.md §1），并补齐测试（AGENTS.md §2）。

### 阶段一：最小可用闭环（含指标实测校准）

**任务**
1. 解决方案骨架 + `scripts/*.ps1`（统一 `D:\dotnet\dotnet.exe`）+ `app.manifest`（PerMonitorV2）
2. `ClipboardMessageWindow`：隐藏消息窗口 + 监听注册/注销 + WndProc
3. `ClipboardAccess`：重试封装 + 锁内拷贝 + 序列号自循环过滤
4. 只处理 `CF_UNICODETEXT`，单表落盘（暂不分 blobs）
5. 面板：右下角弹出、虚拟化列表、`↑↓`/`Enter`/`Delete`/`Esc`、单击即粘贴、关闭按钮
6. 全局热键 `Ctrl+Shift+V` + 失败检测与提示
7. `PasteService`：写回 + `SendInput` Ctrl+V（设置项可关，默认开）
8. **实测校准**：形态 A/B 体积、冷启动、空闲内存、面板弹出延迟
9. 测试：去重/上限/时间格式化单测 + Storage 集成测试 + UIA 冒烟（窗口出现、列表条数、关闭）
10. `SensitiveMasker`（D-13，`Core` 纯函数）：手机号/身份证/银行卡/邮箱/密钥/密码键值脱敏 + 列表显示接入（默认开启）+ 单测

**完成定义（DoD）**：连续复制 20 条文本全部正确记录；重启后记录仍在；`data/` 位于程序目录；粘贴不产生重复记录；`Ctrl+Shift+V` 唤出面板延迟 ≤100ms；**列表里不出现完整手机号/账号**；体积/内存/启动数据落档。

### 阶段二：多格式支持

1. `CF_DIB`/`CF_DIBV5` → PNG（含 32bpp alpha 正确性）
2. `CF_HDROP` 路径记录（长度与非法字符校验，用 `Path.Combine`；绝不读文件内容）
3. `"HTML Format"`（字节偏移解析 + 去标签纯文本 + 写回时 HTML+纯文本双格式）
4. `blobs/` 分离存储 + 内容哈希去重 + 原子写入
5. 缩略图生成与缓存
6. 搜索（`LIKE`，`OrdinalIgnoreCase`，文字 + 文件名）
7. 搜索命中片段与高亮同样走脱敏（匹配用原文，显示用脱敏后文本，D-13）

## 7. 风险登记

| 风险 | 触发条件 | 应对 | 何时验证 |
|---|---|---|---|
| 空闲内存超 80MB | WPF 基线 + 缩略图缓存偏高 | 调 GC 配置（`Server GC` 关闭、`GCConserveMemory`）/ 限制缩略图缓存 / 报告用户后调指标 | 阶段一 |
| 冷启动超 500ms | 单文件压缩 + 首帧 | 关闭单文件压缩或改形态；预热 | 阶段一 |
| `SendInput` 被拦（UIPI） | 目标程序以管理员运行 | 兜底：已写回剪贴板 + 提示手动粘贴 | 阶段二 |
| `GetClipboardOwner` 不可靠 | UWP / 延迟渲染来源 | 以官方"排除"格式为主，进程名过滤可关闭 | 阶段三 |
| U 盘写性能/锁 | 低端 U 盘 + SQLite | `journal_mode=DELETE`、批量写、异步落盘 | 阶段三 |
| 收藏过多导致无法满足磁盘上限 | 用户大量收藏大图 | 提示用户，不自动删除（D-09 边界） | 阶段三 |

### 9.2 已完成项：实现与实测

#### B-01 点击面板外部自动隐藏

| 项目 | 说明 |
|---|---|
| 触发 | 面板失去激活（`Window.Deactivated`）→ 收起面板 |
| 例外 | 右键菜单打开期间不触发，否则菜单刚弹出就被连带收掉 |
| 开关 | 设置页「点击面板外部时自动隐藏」，字段 `hideOnClickOutside`，**默认开启** |
| 实测 | 开关开：点击面板外侧 → 面板消失 ✅；开关关：同样操作面板保留 ✅（双向验证） |
| 备注 | 面板必须激活才收得到键盘输入（D-03 已弃用 `WS_EX_NOACTIVATE`），因此这一条实现成本很低 |

#### B-04 面板透明度（原"亚克力强度"；2026-09-19 定稿：纯半透明，无系统模糊）

| 项目 | 说明 |
|---|---|
| 最终实现 | **纯 WPF 半透明**：只改面板底色 alpha，不碰任何 DWM/窗口合成接口（`Core/Ui/AcrylicTint`） |
| 走过的弯路 | ① `SetWindowCompositionAttribute` + 亚克力(4)：本机 Win11 实测**根本不模糊**（条纹背景下面板亮度标准差 84.99 ≈ 无模糊基线 84.52，只有染色）；② 改模糊(3)：初期能模糊（标准差 →33），但用户实测**过一段时间窗口合成被破坏，内容只剩鬼影**（面板隐藏时反复设置会立刻触发）→ 2026-09-19 整体移除该接口 |
| 强度 | `0–100`：0 = 不透明；越大越透，**封顶 35%**（保底不透明度 65%，按用户要求"别做那么透明"）。映射见 `Core/Ui/AcrylicTint` |
| 即时预览 | 设置页拖动滑杆立即作用到面板；点「取消」或直接关窗自动回退，不写入设置文件 |
| UI | 设置项更名「面板透明度」（字段名保持 `acrylicStrength` 以兼容旧设置文件） |
| 稳定性 | 移除系统模糊后，透明度 80 下反复显示/隐藏面板 8 次全部正常渲染、0 异常（此前系统模糊方案会在使用一段时间后出现鬼影）✅ |

#### B-08 快捷键按键录制（2026-09-19 用户反馈）

| 项目 | 说明 |
|---|---|
| 交互 | 设置页「全局快捷键」改为只读录制框：点击后直接按下组合键即填入规范文本（如 `Ctrl+Shift+V`），Esc 取消并还原；录成功后停止录制，再点一次可继续改 |
| 关键点 | **录制期间宿主必须注销全局热键**（`HotkeyRecordingChanged` 事件 → `HotkeyManager.Unregister`），否则按下的组合会被系统直接吞掉（录不到），还会顺带把面板切出来 |
| 约束 | `HotkeySpec.TryCreate` + `IsSupportedKey` 只接受"有可读名字"的键，保证录制结果一定能被 `TryParse` 读回（否则保存后热键失效）；`ToString` 键名改为可读写法（`PAGEUP` → `PageUp`） |
| 实测 | 录制"当前已注册的 Ctrl+Shift+V"被正确捕获且面板未误弹出；再次点击可录 `Ctrl+Alt+C`；保存后新键唤出面板成功、旧键失效 ✅ |
