## 2. Win32 互操作设计（核心）

### 2.1 CsWin32 配置

- 包：`Microsoft.Windows.CsWin32`；`Interop/NativeMethods.txt` 逐行列出所需 API（白名单式，禁止整包生成）。
- **字符集**：所有字符串 API 一律用 `W` 版本（`GetWindowTextW` 等），避免 ANSI 转换与编码问题。
- **缓冲区别名**：优先选 CsWin32 的 `Span<T>` / `StringBuilder` 安全重载，必须显式传长度；禁止 `Marshal.AllocHGlobal` 手写大小（AGENTS.md §6 缓冲区审查项）。
- 每个调用点上方必须注释：`API 作用 / 调用注意事项 / 资源释放责任`（AGENTS.md 硬性要求）。

`NativeMethods.txt` 白名单：`AddClipboardFormatListener`、`RemoveClipboardFormatListener`、`OpenClipboard`、`CloseClipboard`、`GetClipboardData`、`SetClipboardData`、`IsClipboardFormatAvailable`、`RegisterClipboardFormat`、`GetClipboardSequenceNumber`、`GetClipboardOwner`、`GetWindowThreadProcessId`、`RegisterHotKey`、`UnregisterHotKey`、`CreateWindowEx`、`DestroyWindow`、`DefWindowProc`、`RegisterClassEx`、`GetMessage`、`TranslateMessage`、`DispatchMessage`、`PostMessage`、`GetForegroundWindow`、`SetForegroundWindow`、`IsWindow`、`SendInput`、`DragQueryFile`、`GlobalLock`、`GlobalUnlock`、`GlobalSize`、`SHGetFileInfo`、`Shell_NotifyIcon`、`CreatePopupMenu`、`TrackPopupMenu`、`DestroyMenu`、`GetCursorPos`、`MonitorFromPoint`、`GetMonitorInfo`、`GetDpiForWindow`、`DwmSetWindowAttribute`、`RegSetValueEx`/`RegDeleteValue`。

### 2.2 隐藏消息窗口（`ClipboardMessageWindow`）

| 项 | 设计 |
|---|---|
| 窗口类型 | `CreateWindowEx(0, className, ..., HWND_MESSAGE)`：message-only 窗口可接收定向投递的 `WM_CLIPBOARDUPDATE`/`WM_HOTKEY` |
| 线程 | **创建在 WPF UI 线程（STA）**，复用 WPF 的消息循环（不另起线程、不写第二条消息泵） |
| WndProc 保活 | 委托实例必须由字段持有（否则被 GC 回收 → 回调入无效地址崩溃）；这是 Win32 互操作最经典的坑 |
| 异常隔离 | WndProc 内**全部**代码包在 try/catch 中：异常逃逸出消息循环会直接终止进程 |
| 销毁顺序 | 退出时：`UnregisterHotKey` → `RemoveClipboardFormatListener` → 卸载托盘图标 → `DestroyWindow`（顺序不可颠倒） |
| 重入保护 | 处理 `WM_CLIPBOARDUPDATE` 期间不得递归触发读取（用 `_handling` 标志 + 序列号判定） |

**WndProc 消息表**：

| 消息 | 值 | 处理 |
|---|---|---|
| `WM_CLIPBOARDUPDATE` | 0x031D | 触发一次读取流水线（见 2.3） |
| `WM_HOTKEY` | 0x0312 | 切换面板显隐 |
| `WM_SETTINGCHANGE` | 0x001A | `lParam="ImmersiveColorSet"` → 重新读取系统深浅色 |
| `WM_APP+1` | 自定义 | **后台线程 → STA 线程**的统一入口（粘贴写回、托盘气泡等），`wParam` 为请求 id，数据经线程安全队列取 |
| `TaskbarCreated` | 注册获得 | 资源管理器重启后重新 `NIM_ADD`（否则托盘图标永久消失） |

### 2.3 读取流水线（锁内/锁外边界，AGENTS.md §3 + 需求 §5.3）

```
WM_CLIPBOARDUPDATE
  └─ ClipboardAccess.WithClipboard(retry 3~5 次, 30~50ms, 总上限 250ms)
        ├─ 锁内：seq = GetClipboardSequenceNumber()；命中「自身写入序列号」→ 直接返回
        ├─ 锁内：按优先级探测格式 → 仅拷贝为托管对象（string / byte[] / string[]）
        └─ CloseClipboard()   ← 必须在此之前不做任何编码/IO/UI
  └─ 锁外（后台线程）：HashCalculator → BlobStore.Write(可选) → HistoryRepository.Upsert
  └─ UI 线程：Dispatcher.Invoke 更新列表（增量插入，不整表刷新）
```

- **优先级探测顺序**（需求 §3.2）：`CF_HDROP` → `CF_DIBV5`/`CF_DIB` → `"HTML Format"` → `CF_UNICODETEXT`；命中即停。
- **排除判定**（D-06）：锁内检测 `CanIncludeInClipboardHistory` / `CanUploadToCloudClipboard` 是否为 DWORD 0；锁外按进程名二次过滤（可关闭）。
- **写入侧**：`SetClipboardData` 必须在 STA 线程执行；**后台预生成字节**（大图的 DIB/PNG 转换在后台完成并缓存），STA 线程只做 `SetClipboardData`。
- **空剪贴板/无支持格式**：静默忽略并记一条 debug 日志（不含内容）。

### 2.4 自身写入过滤（需求 §5.1，最高危）

```
写回前：记录 _pendingWriteHash = 内容哈希
写回时：SetClipboardData(...) → 之后读取 seqAfter = GetClipboardSequenceNumber()
判定：收到更新时若 seq == seqAfter → 跳过；否则若 2 秒内哈希 == _pendingWriteHash → 跳过
```

不依赖"写入期间置标志位"的时序假设（官方文档未写明 `WM_CLIPBOARDUPDATE` 是 post 还是 send）。

### 2.5 资源释放责任矩阵（AGENTS.md §6）

| 资源 | 获取者 | 释放责任 | 异常路径 |
|---|---|---|---|
| `OpenClipboard` | 本进程 | 必须在 `finally` 中 `CloseClipboard()`；**且必须在任何慢操作之前** | 重试耗尽 → 记 `GetLastError()` 状态码 |
| `HGLOBAL`（`GetClipboardData` 返回） | 系统所有 | **不得释放**（所有权在剪贴板） | — |
| `HGLOBAL`（喂给 `SetClipboardData`） | 本进程 | 成功后所有权移交系统，**不得再释放**；失败则自行 `GlobalFree` | try/catch 释放 |
| `HICON`（托盘/类型图标） | 本进程 | `DestroyIcon` | try/finally |
| `HMENU`（托盘菜单） | 本进程 | `DestroyMenu` | try/finally |
| `HWND`（消息窗口） | 本进程 | `DestroyWindow` | 退出流程 |
| 剪贴板打开失败 | — | 用 `GetLastError` 判 `ERROR_ACCESS_DENIED` 才重试 | 其它错误直接放弃并记日志 |

### 2.6 托盘图标与菜单

- 用 `Shell_NotifyIcon` 自建封装（**不引 `UseWindowsForms`**，避免为托盘多带一整套框架程序集）。
- `NOTIFYICONDATA.cbSize` 必须为 `Marshal.SizeOf<NOTIFYICONDATA>()`；注册后 `NIM_SETVERSION` 用 `NOTIFYICON_VERSION_4`（否则拿不到 `WM_CONTEXTMENU` 的正确坐标）。
- **菜单点击不消失的经典坑**：弹出菜单前先 `SetForegroundWindow(hwnd)`，`TrackPopupMenu` 返回后 `PostMessage(hwnd, WM_NULL, 0, 0)`。
- 菜单用 Win32 `CreatePopupMenu`/`TrackPopupMenu`（**不用 WPF `ContextMenu`**：托盘点击不会激活窗口，WPF 菜单的焦点模型会导致菜单立即关闭或无法关闭）。
- 处理 `TaskbarCreated` 重新注册图标。

### 2.7 热键与图标提取

- `RegisterHotKey(hwnd, id, modifiers, vk)`：失败（被占用）→ 弹设置窗口提示换键 + 记日志；启动时不静默失败。
- 快捷键字符串 ↔ `MOD_*`/VK 的解析封装在 `Core`（可单测），注册调用在 `Interop`。
- 文件图标用 `SHGetFileInfo`（`SHGFI_ICON | SHGFI_SMALLICON | SHGFI_USEFILEATTRIBUTES`）：后者让不存在的路径也能拿到图标（记录只存路径，文件可能已移动）。

## 3. 线程模型（AGENTS.md §3 铁律的落地形态）

| 线程 | 职责 | 禁止 |
|---|---|---|
| WPF UI 线程（STA） | 创建消息窗口、**全部剪贴板读写**、热键注册、UI 渲染、写回剪贴板 | 做 PNG 编码/哈希/磁盘 IO（除 `settings.json` 小文件） |
| 后台工作线程（`Channel<ClipWorkItem>` 单消费者） | 哈希、PNG 编码、blobs 原子写入、SQLite 写入、缩略图生成 | 触碰任何 Win32 句柄、读剪贴板 |
| 数据传递 | **只传纯托管对象**（`string` / `byte[]` / 值类型 record） | 传 `HGLOBAL`/`HWND`/`IStream` |

- 关闭时序：停止收新工作 → 等待队列排空（超时 2s 强制放弃）→ 注销监听 → 销毁窗口。
- UI 更新统一走 `Dispatcher`，批量合并（同一批入库的多条只触发一次列表刷新）。

## 4. 领域模型与核心算法

### 4.1 模型

```csharp
enum ClipContentType { Text = 1, Html = 2, Image = 3, FileList = 4 }

sealed record ClipItem(
    long Id, ClipContentType Type, string? TextContent, string? BlobPath,
    IReadOnlyList<string> FilePaths, string Preview, string ContentHash,
    long SizeBytes, bool IsPinned, string? SourceApp,
    DateTimeOffset CreatedAt, DateTimeOffset UpdatedAt);
```

`ClipItem` 不可变；列表绑定用轻量 `ClipItemViewModel`（含缩略图、相对时间文案），避免每次刷新重建整表。

### 4.2 格式探测（伪代码）

```
foreach fmt in [CF_HDROP, CF_DIBV5, CF_DIB, "HTML Format", CF_UNICODETEXT]:
    if IsClipboardFormatAvailable(fmt): return Read(fmt)
return null
```

### 4.3 内容哈希

- 文本/路径/HTML：UTF-8 字节的 SHA-256（全量）。
- 图片：**基于规范化像素**（从 DIB 解码为 `BGRA32`、去 stride padding 后重新打包）再做 SHA-256 —— 避免"同一张图因 DIB 头不同/行填充不同"被判为不同内容。
- 哈希在后台线程计算；计算前先校验长度上限（见 4.6）。

### 4.4 去重与入库（原子）

```sql
INSERT INTO clip_items(...) VALUES (...)
ON CONFLICT(content_hash) DO UPDATE SET updated_at = excluded.updated_at;
```

命中冲突即为"重复内容"：只更新时间戳并置顶（需求 §3.3），不新增行；返回 `IsNew=false` 供 UI 决定是否要动画。

### 4.5 淘汰算法（条数上限 + 磁盘上限，D-09）

```sql
-- 条数上限：超出 maxItems 的非收藏项按 updated_at 升序淘汰
SELECT id FROM clip_items WHERE is_pinned = 0
ORDER BY updated_at DESC LIMIT -1 OFFSET @maxItems;
```

磁盘上限：候选集 = 非收藏项按 `size_bytes DESC, updated_at ASC` 排序，在**单个事务**内逐条删除累计至 `used ≤ quota`；`used` 口径 = `SUM(size_bytes) + 元数据文本长度估算`。

- 事务提交后**异步删 blobs 文件**（先提交再删文件，避免"文件已删但事务回滚"的不一致）；孤儿文件由启动时 GC 清理。
- 仅剩收藏仍超限 → 不删，向 UI 发 `QuotaExceededByPinned` 事件提示。
- 淘汰与去重、入库共用同一写队列（单消费者），天然串行，无并发竞态。

### 4.6 输入上限与兜底（AGENTS.md §6「输入信任」）

| 项 | 上限 | 超限行为 |
|---|---|---|
| 文本 | 1MB（UTF-16 字符数按 512K 计） | 截断入库，`preview` 标记"（已截断）" |
| HTML | 4MB | 同上 |
| 图片（DIB 原始字节） | 32MB | 拒绝记录，记 debug 日志 |
| 文件路径条数 | 100 条 | 只取前 100 条 |
| 单条路径长度 | 32767（Win32 长路径上限） | 超长丢弃该条并记日志 |
| 解析异常 | — | 捕获后丢弃本次记录，绝不因单条坏数据崩溃或阻塞监听 |

## 5. 解析器规范

### 5.1 `CF_HDROP`

`DragQueryFile(hDrop, 0xFFFFFFFF, null, 0)` 取条数 → 逐条取长度 → 取字符串。
校验链：长度上限 → 非法字符（`Path.GetInvalidPathChars`）→ `Path.IsPathFullyQualified` → 规范化用 `Path.GetFullPath`（**禁止字符串拼接**）→ 去重保序。**绝不读取文件内容**（需求 §3.2）。

### 5.2 `CF_DIB` / `CF_DIBV5`

- 头判定：前 4 字节 `biSize` → `40`(`BITMAPINFOHEADER`) / `108`(`BITMAPV4HEADER`) / `124`(`BITMAPV5HEADER`)；`biSize` 必须 ≥ 结构体实际所需且有足够字节。
- 行跨距：`stride = ((biWidth * biBitCount + 31) / 32) * 4`；`biHeight < 0` 表示 top-down。
- 像素格式：`biBitCount=32` 时 `CF_DIBV5` 带 alpha（**premultiplied** 需还原为 straight alpha 才能正确编码 PNG）；`CF_DIB` 视为无 alpha（`BGRX`）。
- 越界校验：`biSizeImage` 与 `stride * |biHeight|` 必须小于等于实际数据长度；不满足则拒绝该记录。
- 编码：`BitmapSource.Create(...)` + `PngBitmapEncoder`（WPF 原生，不引 GDI+）。
- 缩略图：≤256px 长边，`DecodePixelWidth` 直接解码缩放（避免大图全解码占用内存）。

### 5.3 `"HTML Format"`

- `RegisterClipboardFormat("HTML Format")` 取 format id；数据为 UTF-8 字节（**必须按字节偏移切片**，不能按 `string` 下标）。
- 头部字段：`Version` / `StartHTML` / `EndHTML` / `StartFragment` / `EndFragment`（十进制 ASCII，行尾 `\r\n`，可能存在额外字段如 `StartSelection`）。
- 解析规则：逐行扫描至第一个非头部行；字段值解析失败按"缺失"处理；`Start*` 允许为 `-1`/超出长度 → 回退策略：`Fragment` 优先，缺失/非法则用 `HTML` 段，仍非法则整段丢弃。
- 纯文本派生：移除 `<script>`/`<style>` 块 → 去标签 → HTML 实体解码（`&nbsp;` 等）→ 折叠空白（供搜索与"HTML 写回时附纯文本"，D-08）。
- 边界校验与畸形样本单测（越界、负值、缺字段、超长、截断到一半的头部）。

| 深浅色 | `AppsUseLightTheme` 注册表 + `WM_SETTINGCHANGE` 监听 | 切换 ResourceDictionary，设置项支持 跟随系统/强制浅/强制深 |

### 6.2 右下角定位算法

```
1. GetCursorPos() → MonitorFromPoint(MONITOR_DEFAULTTONEAREST) → GetMonitorInfo().rcWork（工作区，已排除任务栏）
2. dpi = GetDpiForWindow(panelHwnd)
3. 目标物理坐标 = (rcWork.Right - 宽*pixelScale - 12, rcWork.Bottom - 高*pixelScale - 12)
4. 在 Show() 之前设 WindowStartupLocation=Manual + Left/Top（WPF 用 DIP：物理坐标 / (dpi/96)）
5. 多屏/DPI 变化后重新计算（面板再次弹出时总是重算，不缓存）
```
假设记录：默认落在**光标所在显示器**（对齐 Win+V）；D-05 已确认，可拖动为附加项 B-02。

### 6.3 列表与交互

- 虚拟化：`VirtualizingStackPanel` + `VirtualizationMode=Recycling` + `ScrollUnit=Pixel`，保证 500 条仍流畅。
- 交互矩阵：

| 输入 | 行为 |
|---|---|
| 单击条目 | 写回剪贴板 + `SendInput` 粘贴（`autoPaste=false` 时只写回并提示） |
| ↑ / ↓ | 移动选择（自动滚动到可见） |
| Enter | 同"单击条目" |
| Delete | 删除选中项（含其 blob 文件） |
| Esc | 隐藏面板 |
| 再次按全局热键 | 隐藏面板（D-04） |
| 关闭按钮 | 隐藏面板 |
| 搜索框输入 | 增量过滤（`LIKE`，见 7.3），200ms 防抖 |

> 点击面板外部**不自动隐藏**（D-04 / 附加项 B-01）。

### 6.4 粘贴流程（前台窗口恢复）

```
1. 面板弹出前：_prevFg = GetForegroundWindow()（此时面板尚未显示）
2. 用户触发粘贴：
   a. STA 线程写回剪贴板（预生成字节已在后台备好）
   b. 隐藏面板
   c. if (autoPaste && _prevFg != 0 && IsWindow(_prevFg)) SetForegroundWindow(_prevFg)
   d. 等待 ~50ms（让目标窗口处理激活）→ SendInput(Ctrl+V)
   e. 任一环节失败（UIPI 拦截/前台锁）→ 托盘气泡提示"已复制到剪贴板，请手动 Ctrl+V"
3. _prevFg 为 0/已销毁 → 跳过 c/d，直接走 e 的提示分支
```

### 6.5 敏感信息脱敏显示（D-13）

**定位（务必先读）**：这是**显示层**转换 —— `SensitiveMasker.Mask()` 只作用于渲染路径。**不改变数据库存储、也不改变剪贴板写回内容**：粘贴出去的一定是原文，否则工具失去意义。因此本功能防的是"屏幕被旁人看到 / 截图外泄"，**不防"文件被拷走"**（磁盘仍是明文，Q-1 未解决），README 必须明确写出这条边界。

**默认值**：`maskSensitiveData = true`（默认开启）。

**规则集**（`Core/SensitiveMasker`，纯函数；所有正则 `RegexOptions.NonBacktracking` + 50ms 匹配超时）：

| 规则 | 匹配式 | 可见前缀 | 示例 |
|---|---|---|---|
| 手机号 | `(?<!\d)1[3-9]\d{9}(?!\d)` | 3 位 | `13800138000` → `138******` |
| 身份证 | `(?<!\d)\d{17}[\dXx](?!\d)` | 3 位 | `11010119900307123X` → `110******` |
| 银行卡 | `(?<!\d)\d{13,19}(?!\d)` **且 Luhn 校验通过** | 4 位 | `6222021234567890123` → `6222******` |
| 邮箱 | `[\w.+-]+@[\w-]+(\.[\w-]+)+` | 首字符 + 顶级域 | `alice@example.com` → `a****@*****.com` |
| 密钥/令牌 | `sk-[A-Za-z0-9_-]{8,}`、`ghp_[A-Za-z0-9]{20,}`、JWT 三段 `eyJ…` | 3 位 | `sk-abcdef123456` → `sk-******` |
| 键值型密码 | `(密码\|口令\|password\|passwd\|pwd\|token\|secret\|api[_-]?key)\s*[:=：]\s*\S+` | 仅保留键名 | `密码: hunter2x` → `密码: ******` |

- 掩码样式：`*` × **固定 6 个**（不泄漏原始长度）；前缀不足时按实际长度显示，不补星。
- 多规则命中：按上表顺序执行，**已脱敏区间不再参与后续匹配**（区间合并，避免嵌套规则互相破坏）。
- **误报控制**：长数字串（订单号/时间戳）只有 Luhn 校验通过才脱敏；仍误报时可关闭总开关。白名单/自定义规则第一版不做（附加项 B-05）。

**性能与安全**（AGENTS.md §6「输入信任」，剪贴板内容不可信）：
- 正则必须 `NonBacktracking`（或带超时），禁止可被 ReDoS 的回溯模式。
- 只在**显示时**执行，绝不落库；单次输入上限 64KB，超限只处理前 64KB，尾部以 `…` 收尾。
- 脱敏在 UI 线程执行，必须保证是 O(n) 级、无分配的快速路径（同一 `preview` 文本缓存脱敏结果，避免滚动时重复计算）。

**应用点清单**（一个都不能漏）：
1. 列表条目摘要 `preview` 与任何详情展示
2. 搜索结果的高亮片段（命中位置落在掩码区时整段脱敏）
3. 托盘气泡文案（"已复制 xxx"）
4. `data/logs` 调试行（**先按 50 字符截断，再脱敏**，双保险）
5. 设置页规则预览

**测试用例**（对应 §8.1）：

| 用例 | 期望 |
|---|---|
| 手机号正常 / 前后紧邻数字（`138001380001`） | 脱敏 / 不误伤（边界断言） |
| 16 位数字但 Luhn 不通过（如订单号） | **不脱敏**（误报控制） |
| 带区号固话、含 `-`/空格的卡号 | 按规则是否命中给结果（当前版本不脱敏带分隔符卡号，记为已知限制） |
| 邮箱各种形态（`+` 后缀、多级域名、纯文本里的 email） | 前缀与顶级域可见，其余 `****` |
| 嵌套：HTML 片段含手机号、`密码: abc` 在中文长句里 | 命中并只脱敏目标区间 |
| 超长输入 64KB 边界 / 64KB+1 | 不超时、不抛异常、尾部 `…` |
| 开关关闭（`maskSensitiveData=false`） | 原样返回，且不产生额外分配开销 |

## 7. 存储设计

### 7.1 DDL 与 PRAGMA

```sql
PRAGMA journal_mode = DELETE;    -- 不用 WAL：U 盘/网络盘上 -wal/-shm 残留与锁问题
PRAGMA synchronous  = NORMAL;
PRAGMA foreign_keys = ON;
PRAGMA busy_timeout = 3000;
PRAGMA user_version = 1;         -- 迁移版本号

CREATE TABLE IF NOT EXISTS clip_items (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  type         INTEGER NOT NULL,          -- 1=Text 2=Html 3=Image 4=FileList
  text_content TEXT,                      -- 文本类型全量；其他类型存搜索用摘要
  blob_path    TEXT,                      -- blobs/ 或 pinned/ 下的相对路径
  file_paths   TEXT,                      -- 多路径以 \n 分隔
  preview      TEXT NOT NULL,             -- 列表摘要（≤200 字符）
  content_hash TEXT NOT NULL,
  size_bytes   INTEGER NOT NULL DEFAULT 0,
  is_pinned    INTEGER NOT NULL DEFAULT 0,
  source_app   TEXT,
  created_at   INTEGER NOT NULL,           -- Unix 秒（UTC）
  updated_at   INTEGER NOT NULL
);
CREATE UNIQUE INDEX IF NOT EXISTS ux_clip_items_hash       ON clip_items(content_hash);
CREATE INDEX        IF NOT EXISTS ix_clip_items_updated_at ON clip_items(updated_at DESC);
CREATE INDEX        IF NOT EXISTS ix_clip_items_pinned     ON clip_items(is_pinned);
```

### 7.2 目录与文件协议

- 程序目录定位：`Environment.ProcessPath` → `Path.GetDirectoryName`；**启动时把结果与 `AppContext.BaseDirectory` 一起写入 `--diag` 日志**，两条发布形态各验证一次（需求 §5.6）。
- blobs 命名：`blobs/<hash前2位>/<hash>.<ext>`（分桶避免单目录文件过多）；收藏时复制到 `pinned/<hash>.<ext>`（收藏项永不因淘汰而丢文件）。
- 原子写入：写 `<name>.tmp` → `File.Move(tmp, final, overwrite: true)`；写入前校验磁盘剩余空间（低于 64MB 时拒绝新图片记录并提示）。
- 删除顺序：先删数据库行（事务）→ 后删文件；启动时 GC 扫描 `blobs/` 中无引用文件并清理。
- `data/` 不可写（如放在 `Program Files`）→ 启动即弹窗提示并退出，**不静默降级**。

### 7.3 搜索

`WHERE text_content LIKE @p ESCAPE '\' OR file_paths LIKE @p ESCAPE '\'`，参数化 + 转义 `% _ \`；大小写不敏感用 `COLLATE NOCASE`（ASCII 有效）+ 应用层 `OrdinalIgnoreCase` 二次确认中文场景；结果按 `updated_at DESC`，限量 200 条。

### 7.4 设置持久化（`data/settings.json`）

```json
{ "schemaVersion": 1, "maxItems": 100, "diskQuotaMb": 500, "hotkey": "Ctrl+Shift+V",
  "autoPaste": true, "autoStart": false, "excludedApps": [], "excludeByProcessName": true,
  "captureImages": true, "theme": "system", "maskSensitiveData": true }
```

- 读取：JSON 源生成器上下文（`JsonSerializerContext`，为将来裁剪/AOT 留退路）+ 损坏时回退默认值并备份坏文件为 `settings.json.bad`。
- 写入：临时文件 + 替换（同 7.2 原子写）；写入只在设置界面点"保存"时发生。
- 开机自启：`HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下 `ClipboardManager` 值 = `"<进程路径>"`；程序路径变化时（换盘符/U 盘）在启动时自动纠正；关闭自启则删除该值。**不写 HKLM、不需管理员权限**（需求 §3.5）。

### 7.5 日志

`data/logs/app.log`，单文件上限 2MB × 保留 3 个；**任何剪贴板文本最多记录前 50 字符**（AGENTS.md §4），图片/HTML 只记类型与字节数；`--diag` 追加启动耗时与目录定位明细。

## 10. 安全与隐私审查清单（AGENTS.md §6 落地为可勾选项）

- [ ] 所有 Win32 缓冲区：长度计算有显式上限，无整数溢出（`stride * height` 用 `long` 计算再判上限）
- [ ] 所有句柄：`HICON`/`HMENU`/`HWND`/`HGLOBAL`(自建) 都在 `finally` 或退出流程释放；剪贴板拥有的 `HGLOBAL` 绝不释放
- [ ] `CF_HDROP` 路径：长度 + 非法字符 + `Path.GetFullPath`，无字符串拼接
- [ ] HTML 头：所有偏移量边界校验，无死循环（逐行扫描有最大行数上限）
- [ ] 所有解析入口：长度上限 + 异常兜底，单条坏数据不影响监听循环
- [ ] 无任何网络调用（含遥测）；`grep` 校验发布产物无 `http(s)://` 调用点
- [ ] 日志不含完整剪贴板文本（≤50 字符）、不含文件内容
- [ ] 数据只写程序目录 `data/`；注册表只碰 `HKCU\...\Run`
